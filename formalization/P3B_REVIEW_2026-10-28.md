## Computational trust and resources

`generate_twelve_literal_validity.py` emits candidate syntax and ordinary
Lean proofs. External Python or JSON success is not a proof assumption.
All concrete row proofs are kernel-checked and their dependency closure is
covered by the executed final aggregate audit. The archived native-evaluation
attempt is not in the current Lean source or final dependency closure.

Each compile/audit runs in a guarded Windows process tree: 6144 MiB commit
cap, Lean-internal 2048 MiB limit, one worker, a timeout, named mutex and
system headroom checks. The final build runner uses direct pinned Lake and
Git with a two-process child limit and topological single-target execution.
This prevents overlapping Lean workers without increasing memory limits.

All working data is on D:, with C: compatibility junctions and a separate D:
rollback archive. No page-file settings, toolchain or pinned dependency
revisions were changed.

## Scope boundary

P3-B supplies an exact finite arithmetic certificate and its actual divisor
bridge. It does not supply PNT/gamma, contour estimates, the full analytical
AuxiliaryFamily instance, or any final irrationality-measure number. Those
remain P4–P7 obligations. This acceptance review is not a claim of a new
unconditional numerical pi-power bound.
